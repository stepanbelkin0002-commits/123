# Личное подключение Telegram на Render Free

Приложение для входа в свой Telegram через облачный сервер. Оно показывает
подключённый аккаунт и позволяет сохранить зашифрованную сессию. Интерфейс
работает с телефона. Код входа и пароль двухэтапной проверки вводятся прямо
в форму развёрнутого приложения.

Подготовка исходников не означает, что вход уже выполнен: приложение сначала
нужно разместить в своём аккаунте Render и подтвердить вход.

## Запуск

При подключённом плагине Render подготовку сервиса можно продолжить в чате.
Для самостоятельного развёртывания:

1. Зарегистрируйся на https://dashboard.render.com/ и создай репозиторий на
   GitHub, GitLab или Bitbucket. Загрузи в него файлы из этой папки.
   Реальные ключи и пароли в репозиторий не добавляй.
2. На Render создай **Web Service**, выбери этот репозиторий и тариф **Free**.
3. Runtime: **Python 3**.
4. Build Command: `pip install --no-cache-dir -r requirements.txt`.
5. Start Command:

   ```sh
   uvicorn main:app --host 0.0.0.0 --port $PORT --workers 1 --no-access-log
   ```

6. Health Check Path: `/health`.
7. В **Environment** добавь:

   | Переменная | Значение |
   |---|---|
   | `TG_API_ID` | API ID существующего приложения с my.telegram.org |
   | `TG_API_HASH` | API hash того же приложения |
   | `DASHBOARD_PASSWORD` | Свой уникальный пароль панели, не менее 24 символов |
   | `PYTHON_VERSION` | `3.12.12` |

   Сохрани пароль панели: он нужен для доступа и восстановления сохранённой
   сессии. Настоящие значения не следует добавлять в README или исходники.

8. Запусти развёртывание и открой полученный адрес `https://….onrender.com`.
9. Введи пароль панели, номер нужного Telegram-аккаунта, затем код входа и,
   если запрошен, пароль двухэтапной проверки.
10. Убедись, что на странице показан именно нужный аккаунт.

Альтернатива ручным настройкам сервиса — Render Blueprint из `render.yaml`.
В файле задан один сервис на тарифе `free`, без платных дисков и баз данных.
Ключи и пароль при создании Blueprint вводятся владельцем отдельно.

## Сохранение входа

Render Free останавливает неактивные приложения и не сохраняет изменённые
локальные файлы после остановки. Поэтому приложение держит сессию в памяти,
а для восстановления использует секрет окружения:

1. После успешного входа нажми **Подготовить сохранение** → **Скопировать**.
2. В Render → **Environment** добавь `TG_SESSION_ENCRYPTED` со скопированным
   зашифрованным значением.
3. Сохрани изменения и дождись нового запуска сервиса.
4. Открой панель и проверь, что аккаунт подключён и сессия загружена из настроек.

Сессия зашифрована AES-GCM. Ключ выводится из `DASHBOARD_PASSWORD` с помощью
scrypt. Соль и nonce генерируются отдельно для каждого сохранения. При
изменении пароля панели старое сохранение перестанет расшифровываться.

Само это сохранение не запускает приложение круглосуточно. Free-сервис
может засыпать после 15 минут без входящих HTTP/WebSocket-запросов; новое
открытие страницы запускает его заново с задержкой. Приложение не содержит
обхода спящего режима. Для регулярной публикации потребуется отдельная
настройка расписания и проверка ограничений тарифа.

## Что делает приложение

- Запрашивает код входа и подтверждает его, при необходимости проверяет 2FA.
- Через `get_me` показывает имя и идентификатор подключённого аккаунта.
- Выдаёт зашифрованное сохранение текущей сессии только владельцу панели.
- Ограничивает повторные запросы кода и учитывает `FloodWait` Telegram.

Ограниченная команда владельца может публиковать подготовленные посты только
в указанном собственном канале. История личной переписки не читается.
«Закрыть панель» закрывает доступ в браузере; сессия Telegram остаётся
действительной. Для её отзыва используй в официальном Telegram
**Настройки → Устройства** и заверши соответствующий сеанс, затем удали
`TG_SESSION_ENCRYPTED` с Render.

## Создание канала владельцем

Модуль `channel_setup.py` поддерживает одну ограниченную команду создания
новостного канала из `TG_CHANNEL_SETUP_JSON` в Environment на Render.
Публичного HTTP-метода для запуска команды нет. Параметры включают название,
описание, варианты username, уникальный идентификатор и срок действия команды.
Команда использует только уже сохранённую авторизованную сессию и не запрашивает
новый код входа. После выполнения оператор очищает переменную команды.

Перед созданием проверяются метаданные собственных каналов с тем же названием,
описанием и недавней датой создания. Повторный запуск переиспользует найденный
канал. При неоднозначности выполнение останавливается. Поиск охватывает весь
список диалогов, а время работы ограничено сроком команды. Текст переписки
не используется и не выводится в результаты.

Команда выполняется после паузы в 150 секунд, чтобы предыдущий экземпляр Render
успел закрыть Telegram-соединение. Автоматический повтор запроса создания
отключён. Платные username не покупаются, существующие каналы не удаляются.
Результат `CHANNEL_SETUP_RESULT` содержит только метаданные нового канала;
сессия, пароль, API hash и access hash в журнал не записываются.

По отдельному запросу владельца флаг `archive_existing_dialogs` переносит
остальные диалоги в Архив. Созданный канал остаётся в основном списке.
Удаление личных чатов и сообщений не используется. По отдельному запросу
владельца флаг `leave_unavailable_channels` вызывает выход для объектов
`ChannelForbidden` и для частных каналов, чью недоступность Telegram подтвердил
ответом `CHANNEL_PRIVATE` или `CHANNEL_PUBLIC_GROUP_NA`. Доступные частные
каналы под это действие не попадают. Перед архивированием старые закреплённые
диалоги открепляются; новый управляемый канал исключён из уборки.
Архивирование выполняется до проверки доступности частных каналов. Между
проверками выдерживается пауза в две секунды; короткий `FloodWait` при чтении
метаданных соблюдается с ограниченным повтором. Создание канала автоматически
не повторяется. Время одной команды ограничено 15 минутами и её сроком действия.
Опция удержания чатов в архиве меняет только `keep_archived_unmuted`, сохраняя
прочие настройки учётной записи. В журнал выводятся только суммарные счётчики,
без названий и содержания личных чатов.

Повторные команды для известного канала могут указывать `existing_channel_id`
вместе с `allow_create: false`. Тогда используется только указанный собственный
канал, даже если он создан раньше окна выполнения команды. Устаревшие записи
мигрировавших групп не учитываются как видимые диалоги основного списка.

Команда `action: publish_posts` принимает до трёх готовых текстов в `posts`,
требует `existing_channel_id`, `allow_create: false` и отключённые флаги уборки.
Перед отправкой проверяется владение каналом и наличие идентичного поста среди
его последних 30 записей. Стабильный `random_id` предотвращает повторную отправку
после перезапуска. Каждая публикация сверяется с историей только этого канала;
журнал содержит идентификатор и публичную ссылку, без содержимого переписки.
Это разовая команда, а не постоянно работающий редакционный планировщик.

Команда `action: edit_posts` правит до трёх известных публикаций по `message_id`.
Для каждой обязательны прежний `expected_text` и новый `text`; поддерживаются
обычный текст и `parse_mode: html`. Перед правкой проверяются владение каналом
и точное совпадение прежнего текста. При другом тексте или отсутствии поста
выполнение останавливается без создания замены. Повтор уже применённой правки
не создаёт новых сообщений. Редакционная подача описана в `editorial/style.md`.

Приложение рассчитано на одного владельца, один процесс и один экземпляр.
При смене домена задай `APP_ORIGIN` равным полному HTTPS-адресу сервиса без
пути и завершающего слеша. Стандартный адрес берётся из `RENDER_EXTERNAL_URL`.
Проверки Origin, Host, CSRF и cookie Secure требуют HTTPS.

## Проверка без настоящего аккаунта

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Тесты используют поддельный Telegram-клиент. Они не отправляют коды,
не подключаются к Telegram и не требуют реальных ключей. Для проверки
JavaScript: `node --check static/app.js`.
